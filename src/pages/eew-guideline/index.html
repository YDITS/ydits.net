緊急地震速報ガイドライン 対応状況

  • 概要

    YDITS の運営者『よね/Yone』は、地震動の予報業務許可事業者《緊急地震速報(業)》ではありません (2026年4月現在)。
    気象業務法における独自の予測・計算は行っておらず、国土交通省 気象庁、(一財)気象業務支援センター、予報業務許可事業者、または配信事業者が発表した情報をそのまま配信しています。
    しかしながら、YDITS では緊急地震速報の適切な取り扱いを徹底するために、気象庁が取りまとめる「緊急地震速報を適切に利用するために必要な受信端末の機能及び配信能力に関するガイドライン」への対応状況を表記します。

  • 気象庁が緊急地震速報(予報)等を発表してから最初の報知を開始するのに要する時間

    当サービスでは、配信事業者から緊急地震速報(予報)等を受信するため、気象庁が緊急地震速報(予報)等を発表してから配信事業者が最初の報知を配信を開始するのに要する時間は、その配信事業者に依存します。
    配信事業者が配信してから当サービスが最初の報知を開始するのに要する時間は次のとおりです。

    • YDITS for Web アプリケーション

      アプリケーションで配信事業者と直接接続し受信します。当サービスからの配信はありません。

    • YDITS API

      配信事業者が配信してから、1秒以内に当サービスのAPIによる配信開始をするように実装しています。
      ただし、インターネット回線及びインターネットサービスプロバイダを経由するため、通信状況等によって緊急地震速報(予報・警報)をユーザーに配信するのに1秒以上遅延したり、配信を受けられない場合があります。

  • 気象庁から端末まで配信を途切れさせないような十分な対策をとっているもの

    当サービスでは、配信事業者から緊急地震速報(予報・警報)を受信するため、気象庁から配信事業者サーバーまで配信を途切れさせないような対策は、その配信事業者に依存します。
    配信事業者から当サービスまで配信を途切れさせないような対策は次のとおりです。

    • YDITS for Web アプリケーション

      アプリケーションで配信事業者と直接接続し受信します。当サービスからの配信はありません。

    • YDITS API

      配信事業者から当サービスのサーバーまでは、当方が所有するサーバーとクラウドサービスが提供するサーバーの2つによるシステム的かつ地理的な冗長化を行っています。
      ただし、インターネット回線及びインターネットサービスプロバイダを経由するため、通信状況等によって緊急地震速報(予報・警報)をユーザーに配信するのに1秒以上遅延したり、配信を受けられない場合があります。

  • 時刻の誤差が常に±１秒以内となるよう時刻合わせしているもの

    当サービスのサーバーはNTPにより常に時刻同期を行い、誤差が1秒未満となるようにしています。
    ユーザーの端末は時刻設定によりますが、アプリケーションではユーザーの端末の設定時刻を参照せずサーバーから正確な時刻を常に取得するため、ユーザーの端末の時刻に誤りがあっても支障が生じないよう実装しています。

  • 配信・許可事業者によるサポートが充実しているもの

    ガイドラインの推奨のとおりです。
    当サービスへの連絡は、当方のお問い合わせフォーム で対応します。

  • 耐震固定等地震の揺れへの対策を推奨

    当方が所有するサーバーの所在地は東京、クラウドサービスが提供するサーバーの所在地は東京、大阪、又はその他 による地理的な冗長化を行い、万一揺れ等により片方が使用不能になった場合でもシステム全体の配信は支障が生じないよう構築しています。

  • 無停電化を推奨

    当方が所有するサーバーの所在地は東京、クラウドサービスが提供するサーバーの所在地は東京、大阪、又はその他 による地理的な冗長化を行い、万一停電等により片方が使用不能になった場合でもシステム全体の配信は支障が生じないよう構築しています。

  • サーバーから端末までの回線は常時接続できる回線を使用することが必須

    配信事業者から当サービスのサーバーまでは、WebSocketによる常時接続を実施します。
    当サービスからユーザーまでの常時接続できる回線を使用することへの対応は次のとおりです。

    • YDITS for Web アプリケーション

      アプリケーションで配信事業者と直接WebSocketによる常時接続を行います。当サービスからの配信はありません。

    • YDITS API

      現在のところ、REST APIによるポーリング方式を提供しており、緊急地震速報は最短のポーリング間隔を 1000ミリ秒=1秒 と規定しています (2026年4月現在)。
      WebSocket による常時接続に対応するよう、開発を進めています。

  • 猶予時間がない場合でも報知させることを推奨

    猶予時間に関わらず報知します。
    なお、主要動到達予想時刻については、当サービスは気象業務法における独自の予測・計算は行っておらず、気象庁が発表する緊急地震速報(警報)の各対象地方予報区の主要動到達予想時刻をそのまま表示します。

  • 猶予時間＋10秒程度は安全確保を促す報知を継続させることを推奨

    次のとおりです。

    • YDITS for Web アプリケーション

      緊急地震速報(警報)の場合には、受信してからおよそ8秒間報知音を鳴らします。ただし、ブラウザの制限、または音量やミュート等により鳴らない場合があります。
      また、ユーザーの現在位置の地方予報区が、気象庁が発表する緊急地震速報(警報)の対象の場合、画面に身を守るためのメッセージ（『強い揺れに警戒、身を守ってください』等）を表示します (位置情報を許可する必要があります。)。

    • YDITS API

      緊急地震速報(予報・警報)の電文を提供するものであるため、該当しないものとします。
      なお、安全確保を促す固定付加文等 (『強い揺れに警戒してください』等) については、気象庁が発表する情報をそのまま配信します。

  • 端末利用者が必要とする設定震度を超えたときに報知させることを推奨

    次のとおりです。

    • YDITS for Web アプリケーション

      現在のところ、ユーザーが報知させる震度を任意に設定することはできません。
      報知音を鳴らすかどうかは、次の条件でオンまたはオフに設定できます。
      - 予想最大震度が変化したとき
      - キャンセル報が発表されたとき

      ただし、ブラウザの制限、または音量やミュート等により鳴らない場合があります。

    • YDITS API

      緊急地震速報(予報・警報)の電文を提供するものであるため、該当しないものとします。

  • 複数観測点のデータに基づく緊急地震速報(業)で報知させることを推奨

    次のとおりです。

    • YDITS for Web アプリケーション

      アプリケーションで配信事業者と直接接続し受信します。配信事業者の配信によります。

    • YDITS API

      配信事業者の配信によります。

  • 震度の予想の方法が従来法に基づく場合は、深発地震では正確な震度の予想は困難なことから報知させないことを推奨

    次のとおりです。

    • YDITS for Web アプリケーション

      アプリケーションで配信事業者と直接接続し受信します。配信事業者の配信によります。

    • YDITS API

      配信事業者の配信によります。

  • 最初にNHKチャイム音を用いた報知をさせることを推奨

    次のとおりです。

    • YDITS for Web アプリケーション

      NHKチャイム音を使用していません。
      緊急地震速報(予報)の場合には独自の音声「緊急地震速報です。最大震度〇と推定される地震が発生しました。」を、緊急地震速報(警報)の場合には独自の警報音「ピー、ピー...」と独自の音声「緊急地震速報です。強い揺れに備えてください。×2回」を鳴動させて報知します。

    • YDITS API

      緊急地震速報(予報・警報)の電文を提供するものであるため、該当しないものとします。

  • 予想した震度や猶予時間については具体的に報知させないことを推奨。ただし、端末利用者が緊急地震速報(業)の誤差や技術的限界について理解していれば、具体的な予想震度、猶予時間を報知させる選択もあるが、震度の予想がPLUM法に基づく場合は具体的な猶予時間は算出できないため、猶予時間について報知させる場合には、「まもなく到達」等の表現を用いることを推奨する。なお、震源の位置とマグニチュードが「仮定震源要素」である場合は、震度の予想がPLUM法に基づく場合を除き、予想した震度を報知させないこと

    次のとおりです。

    • YDITS for Web アプリケーション

      ユーザーの現在位置の地方予報区が、気象庁が発表する緊急地震速報(警報)の対象の場合、気象庁が発表する緊急地震速報(警報)の各対象地方予報区の予想震度及び主要動到達予想時刻を表示します (位置情報を許可する必要があります。)。
      予想震度及び主要動到達予想時刻については、当サービスは気象業務法における独自の予測・計算は行っておりません。

    • YDITS API

      緊急地震速報(予報・警報)の電文を提供するものであるため、該当しないものとします。
      気象庁が発表する緊急地震速報(警報)の各対象地方予報区の予想震度及び主要動到達予想時刻をそのまま配信します。
      緊急地震速報(予報)は、当サービスは気象業務法における独自の予測・計算は行っていないため、予想震度及び主要動到達予想時刻を配信しません。

  • 予想した震度または猶予時間を報知している場合は、予想した震度が大きくなる場合または猶予時間が短くなる場合に報知内容を変更することを推奨。それ以外の場合は、報知内容は変更しないことを推奨

      予想震度及び主要動到達予想時刻については、当サービスは気象業務法における独自の予測・計算は行っておりません。

      気象庁が発表する緊急地震速報(警報)の各対象地方予報区の予想震度及び主要動到達予想時刻をそのまま配信します。
      緊急地震速報(予報)は、当サービスは気象業務法における独自の予測・計算は行っていないため、予想震度及び主要動到達予想時刻を配信しません。

  • 報知した緊急地震速報(業)に対してのキャンセル報が提供された場合は、キャンセルされた旨を報知させることを推奨。報知しなかった緊急地震速報(業)に対してのキャンセル報は、報知させないこと

    ガイドラインの推奨のとおりです。

  • テスト報を受けて行う端末の試験の実施を推奨。普段はテスト報を受けても端末が動作しないように設定しておくことを推奨

    次のとおりです。

    • YDITS for Web アプリケーション

      テスト報を受けて行うアプリケーションの試験は実施していません。アプリケーションがテスト報を受信してもユーザーに表示しません。

    • YDITS API

      配信事業者からのテスト報は配信しません。
      当サービスが独自に実施するテストについては、原則実施しませんが、もしも実施する場合は事前に通知します。API仕様のとおり、テスト報かどうかのフラグを確認する実装をするようお願いしています。

  • 端末が持つ訓練機能による報知または訓練報を受けての報知を見聞きしての訓練の実施を推奨。普段は訓練報を受けても端末が動作しないように設定しておくことを推奨

    次のとおりです。

    • YDITS for Web アプリケーション

      訓練機能による報知または訓練報を受けての報知を見聞きしての訓練は実施していません。アプリケーションが訓練報を受信してもユーザーに表示しません。

    • YDITS API

      配信事業者からの訓練報は配信しません。
      当サービスが独自に実施する訓練については、原則実施しませんが、もしも実施する場合は事前に通知します。API仕様のとおり、訓練報かどうかのフラグを確認する実装をするようお願いしています。
